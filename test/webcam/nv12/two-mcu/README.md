# Two-MCU buffering against stock-fast-exact NV12

This branch tests serial entropy decoding of two MCUs followed by their
reconstruction, using the existing stock-fast-exact paired Y and Cb/Cr kernels.
It adds a 512-byte coefficient buffer and changes only `jdcoefct-8.c.o` in
otherwise hash-verified no-PGO codec archives. Inline AVX2 zeroing is retained.
Production src/simd and previous selections remain unchanged.

## Decision

Park both variants: neither demonstrates a repeatable whole-frame benefit.
Both compiler means increased in both cohorts. These sub-1% means overlap
noise, so they are not precise proof of a slowdown. In the shared-dispatch
cohort, one Clang identical-binary bracket was +11.46%; it is retained rather
than discarded. No further revision or confirmation cohort was run because
neither implementation established a gain worth pursuing. Keep the previous
stock-fast-exact and reduced-UV selections.

## Results

Positive percentages mean more time (slower). All measurements are whole
JPEG-to-NV12 decode, including normal setup and teardown, with input loading,
allocation and output hashing outside the timed region.

| Variant | Compiler | Control ms | Candidate ms | Time change |
|---|---|---:|---:|---:|
| Buffering only | clang | 3.1805 | 3.1982 | +0.56% |
| Buffering only | gcc | 3.3774 | 3.3936 | +0.48% |
| Shared dispatch | clang | 3.1960 | 3.2210 | +0.78% |
| Shared dispatch | gcc | 3.3903 | 3.4149 | +0.72% |

Each cohort uses five control/candidate/control brackets per compiler,
three passes over the last 90 preloaded capture frames. Identical-binary noise
controls use the same schedule and are retained in each summary. Compiler and
comparison order rotate. The saved runner also supports a separate confirmation cohort; it was not
needed or executed here. All raw rounds are saved, including regressions.
CPU 0 on Ryzen 9 3900X; matched O3 and LTO (Clang ThinLTO/GCC LTO), no PGO
and no explicit mtune/march/mcpu. Entropy retains matched BMI2. Native support
is identical within each pair. Compilation and validation do not overlap timing.

## Implementations and interpretation

`controller.patch`: decode both buffers first, then call ordinary reconstruction
twice. Entropy state remains serial. Static assembly still has two fusion
reconstruction dispatch calls, so buffering alone does not remove those calls
or provide parallel execution. Its measured change overlaps noise.

`paired-controller.patch`: one focused revision calls a shared reconstruction
entry point for the pair. It caches quantizer/output pointers and dispatches
directly to the same four native kernel calls. No arithmetic or reconstruction
order changes. The wrapper is regenerated by `build.py`; generated source and
disassembly remain under /tmp. Static assembly is context, not cycle attribution.

## Correctness and fallback behavior

`check.py` compares complete validation reports with matched controls for all
120 captures, six boundary fixtures (dense, zero-AC, optimized tables,
progressive, per-MCU restart and high-frequency tail), quantizer mutations and
mixed streams. Literal array comparisons inside the driver verify stock-fast
mode 3, luma, accurate fallbacks and output padding. Modes 1/2 keep the previous
single-MCU schedule. Progressive decoding retains its ordinary multipass path.

A dedicated harness compares ordinary and suspended decoding literally,
including padded Y/UV buffers. Across 14 inputs per compiler/variant it forces
52,740 suspensions using 97- and 4093-byte reveal increments; 26,578 resumes
have odd MCU columns. Generated 16x8, 48x24 and 80x16 4:2:2 images with per-MCU
restarts exercise one-MCU rows and odd final-MCU tails. These are synthetic
YCbCr inputs, not additional real capture scenes. The harness feeds headers
before restricting input, so it does not claim suspended progressive startup.
If the second MCU suspends, the first committed MCU is reconstructed before
return and resume begins at the second. Stack-local coefficients are never
needed after return. All target output bytes and padding match the controls.

`audit.py` checks binary/archive hashes and absence of PGO metadata/options,
and retains controller disassembly. GCC's reported generic march/mtune options
are compiler defaults, not explicit tuning flags. Both archives change only
the 8-bit controller member; entropy and the other precisions are unchanged.

## Reproduce

Prerequisites are the no-mtune baseline, next-round source recovery and the
paired-fast-chroma build documented in their folders. Retained /tmp artifacts
are disposable; this experiment adds no new external dependency.

```
python3 test/webcam/nv12/two-mcu/build.py
python3 test/webcam/nv12/two-mcu/check.py
python3 test/webcam/nv12/two-mcu/audit.py
python3 test/webcam/nv12/two-mcu/run.py
python3 test/webcam/nv12/two-mcu/build.py --paired-entry
python3 test/webcam/nv12/two-mcu/check.py --paired-entry
python3 test/webcam/nv12/two-mcu/audit.py --paired-entry
python3 test/webcam/nv12/two-mcu/run.py --paired-entry
# Separate confirmation, when needed:
python3 test/webcam/nv12/two-mcu/run.py --paired-entry --confirm
```

One capture scene on one CPU limits generalization. No changes were committed
or pushed. The existing preferred reduced and separate exact-fast selections
are preserved; no measured small change automatically changes those selections.
