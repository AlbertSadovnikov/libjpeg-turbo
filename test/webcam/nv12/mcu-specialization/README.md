# Four-block MCU entropy specialization

On the Ryzen 9 3900X, explicitly expanding Y/Y/Cb/Cr did not improve the fast-IDCT JPEG-to-NV12 path. Keep the existing decoder. Production codec sources are unchanged; the patches here apply to the retained threshold-pair10 entropy prototype.

Three alternatives preserve the generic decoder and select the new path only for full-resolution raw-output 8-bit YCbCr 4:2:2 scans with the expected four-block layout and all components needed:

- `unroll4`: four copies of the generic block body, with literal block indices.
- `special4`: four copies with fixed DC predictor indices (0,0,1,2), shared Y tables, and no per-block component-needed or null-output branches.
- `special-loop`: the same specialization in a compact four-iteration loop.

Scan layout checks run once per scan. Non-null block checks run at MCU dispatch. Restart, input-budget, marker rollback and generic fallback behavior remain in place. The bitstream and DC dependencies remain serial across blocks.

## Results

Mean end-to-end latency, milliseconds per 1920×1080 frame. Percentages are latency changes relative to the matching compiler baseline; positive is slower.

| Variant | GCC accurate | GCC fast | Clang accurate | Clang fast |
|---|---:|---:|---:|---:|
| Baseline | 4.282 | 3.902 | 4.260 | 3.905 |
| Unroll four | 4.268 (−0.33%) | 3.913 (+0.29%) | 4.312 (+1.23%) | 3.919 (+0.36%) |
| Specialize four | 4.355 (+1.70%) | 4.035 (+3.40%) | 4.417 (+3.70%) | 4.088 (+4.68%) |
| Compact specialization | 4.371 (+2.07%) | 3.986 (+2.15%) | 4.321 (+1.44%) | 3.905 (+0.02%) |

Three rotated/reversed rounds on CPU 0, 90 held-out preloaded camera frames, three measured passes after a full warmup. GCC 13.3 and Clang 18.1, matched baseline flags, no PGO or LTO. Only `jdhuff.c.o` changes in each archive; all other members were verified byte-identical. These measurements use the existing native NV12 sequence path, without the later fused chroma kernels, to isolate the entropy change. They do not replace the previously measured fused-path best latency.

All candidates match their baselines' NV12 hashes on 120 camera frames and six fixtures (restart interval 1, optimized Huffman tables, progressive, dense AC, coefficient 63, zero AC), in both IDCT modes. This is targeted validation, not exhaustive malformed-input or fallback coverage.

## Generated code

Total bytes of emitted `decode_mcu*` functions, including retained generic/fallback code:

| Variant | GCC bytes | Clang bytes |
|---|---:|---:|
| Baseline | 7,086 | 5,494 |
| Unroll four | 26,817 | 21,379 |
| Specialize four | 21,440 | 15,912 |
| Compact specialization | 10,830 | 8,666 |

GCC inlines the expanded specialized body into MCU dispatch and retains a separate generic fast function. Clang keeps a separate specialized function. GCC's fully specialized dispatch also has more static stack-memory operand sites than the baseline (213 versus 138). These are code-size and register-pressure observations, not measured cache-miss counters; they do not establish the cause of the regression. Removing layout checks and table indexing did not create useful independence in the serial entropy chain.

## Artifacts and reproduction

`build.py` creates six isolated builds and reviewable patches. It requires the retained `/tmp/mjpeg-stb-src/threshold-pair10`, `/tmp/mjpeg-pgo-lto` baseline builds and common sequence/embedded-frame objects, and `/tmp/mjpeg-google-bench`. It deliberately refuses to overwrite existing candidate trees. `run.py` requires the six generated fixtures in `/tmp/mjpeg-lut-pipeline/fixtures` (generated by the adjacent LUT experiment).

```
python3 test/webcam/nv12/mcu-specialization/build.py
python3 test/webcam/nv12/mcu-specialization/run.py
python3 test/webcam/nv12/mcu-specialization/audit.py
```

`experiment.json` records build locations and flags; `isolation.json` records archive isolation; `results.json`, `summary.json` and `validation.json` record measurements and hashes. `audit/summary.json` records code sizes and static stack operand counts. The audit verifies that adding debug information leaves `.text` byte-identical to the measured archive member. Generated annotated assembly is local and ignored by Git.
